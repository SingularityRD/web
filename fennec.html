Why Fennec

Six reasons to choose Fennec

01 · Developer speed

A scanner fast enough to stay switched on

When a scan takes minutes, developers disable it and bugs ship with the next release. Fennec scans in seconds, runs where developers already work and shows only the issues each change adds. The check stays on, and problems are fixed at the keyboard, where fixing costs least.

  • Runs on every save, commit and pull request
  • Diff mode shows only what a branch adds

02 · One tool

One tool instead of three separate scanners

Many companies buy code, secret and dependency scanning separately, and still cannot say what is in their code. Fennec checks all of it in one pass, plus configuration files and encryption. One tool to roll out, one report to read.

  • Follows untrusted input across files to where it harms
  • Passwords, keys and tokens stopped before they are committed

The crypto inventory banks are now asked for

Banks, defense suppliers and critical infrastructure are being asked where their encryption stands. RSA and elliptic-curve crypto must be replaced on CNSA 2.0 timelines, the US schedule for quantum-safe encryption. Fennec finds every use, scores your readiness and writes the inventory in one run.

  • Finds RSA, DSA, elliptic-curve and Diffie-Hellman use
  • Migration deadline shown for every finding
  • Credits quantum-safe algorithms such as ML-KEM and ML-DSA
  • A readiness percentage you can show the board
  • Crypto bill of materials (CBOM) in CycloneDX format

04 · Fits your stack

Switch without rewriting the rules you trust

Your team has written rules for the scanner it uses today. Fennec reuses them without a rewrite and plugs into the places code is reviewed, from pull requests to any CI pipeline. Even AI coding agents can check their own code before you see it.

False alarms teach developers to ignore a scanner. Every Fennec rule is tested in CI against vulnerable code and look-alike safe code. Known false-positive patterns are published, and in the pilot accuracy is measured again on your code, not ours.

  • Batch ignore or baseline, previewed before anything changes

06 · Evidence

Software companies face customer security reviews and SOC 2 audits. Banks face strict regulators. AI now writes more of the code, and Fennec checks all of it. The same scans produce the standard reports auditors and customers ask for.

Questions buyers ask

Questions about Fennec

What is Fennec, in one sentence?

Fennec is Singularity’s code security scanner: in seconds it checks your code for security bugs, leaked secrets, vulnerable open-source libraries, risky configuration and quantum-weak encryption, on developer laptops, in pull requests and in any CI pipeline.

Can Fennec run on-premises or in an air‑gapped network?

Yes. Fennec runs on your own machines, on macOS, Linux and Windows, and your code never leaves them. An air-gapped install is available. Code, secret and crypto scans run fully offline; only dependency checks look up the public OSV vulnerability database.

Who decides what blocks a build and what gets ignored?

Your team does. With Fennec you choose which severity fails a build. Accepting a finding takes an in-code note that reviewers see in the pull request, and bulk changes are previewed before anything is written. Automatic fixes apply only when you run them.

Will Fennec slow my developers down?

No. Fennec scans in seconds, fast enough to run before every commit, and shows only the issues a branch adds rather than the whole backlog. Developers see findings where they already work: the command line, VS Code, pre-commit and pull requests.

Won’t it bury my team in false positives?

Fennec tests every rule against vulnerable code and against look-alike safe code, which must produce zero findings. Each rule is labeled by tier so you can tune noise, and in the pilot Fennec’s accuracy is measured again on your own code.
